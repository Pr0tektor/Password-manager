Менеджер паролей — руководство пользователя

Версия 1.2.0. Русский интерфейс и English доступны в одном приложении.

1. Что входит в комплект

Приложение хранит логины, пароли, адреса сайтов и заметки в зашифрованном виде в вашем браузере. Есть поиск, генератор паролей, импорт из Chrome, зашифрованные резервные копии, установка PWA и дополнительное сохранение копий в Google Drive.

В комплекте: исходные файлы, русское и английское руководства, страница docs/guide.html для чтения и печати, файлы запуска Windows и автоматические тесты. Кнопка «Помощь» открывает руководство. Для обычного использования программировать не нужно.

Это первая версия без независимого аудита безопасности. Начните с тестовых записей. Забытый мастер-пароль восстановить нельзя. Google-аккаунт также не сможет открыть копию без мастер-пароля.

2. Первый запуск на компьютере

Обычное использование по ссылке

Устанавливать Node.js и держать окно сервера открытым пользователю не требуется. Владелец размещает приложение один раз, после чего пользователи открывают его по ссылке.

Открыть приложение. Версия размещена на GitHub Pages через HTTPS и доступна на компьютере и телефоне.

  1. Откройте HTTPS-адрес приложения в Chrome, Edge или Safari.
  2. Выберите язык и создайте хранилище, как описано ниже.
  3. Нажмите Установить, дождитесь готовности офлайн-режима и установите приложение через меню браузера.
  4. В дальнейшем запускайте его по иконке. После успешного кэширования оно работает без сети, пока браузер сохраняет данные приложения.
  5. После добавления важных записей сохраните зашифрованную резервную копию.

На телефоне используйте тот же HTTPS-адрес, но перенесите хранилище через зашифрованную копию: данные не синхронизируются автоматически. Подробности установки — в разделе 10.

Локальный запуск для разработки или собственной копии

  1. Скачайте ZIP репозитория GitHub через Code → Download ZIP и распакуйте его в отдельную папку.
  2. Нужен Node.js 22 или новее с официального сайта.
  3. На Windows откройте Запустить.cmd / Start.cmd; в других системах выполните npm start в папке проекта.
  4. Откройте http://localhost:4173. Для первой загрузки и подготовки офлайн-кэша сервер должен работать. Остановить его можно сочетанием Ctrl+C.
  5. После сообщения о готовности офлайн-режима проверьте повторный запуск с выключенным сервером и тестовыми данными. Для обновления локальной копии снова запустите сервер.

Устанавливать библиотеки через npm install не требуется. Двойной щелчок по index.html не поддерживается: шифрование, модули и PWA работают через localhost либо HTTPS.

Сервер слушает только этот компьютер. Адрес localhost на телефоне обозначает сам телефон. На телефоне используйте опубликованную HTTPS-версию. Для переноса записей с localhost на публичный адрес сначала сохраните зашифрованную копию, затем восстановите её по новому адресу: это разные хранилища.

3. Выбор языка

В верхней части нажмите English, чтобы включить английский интерфейс. Кнопка Русский вернёт русский. Выбор запоминается в этом браузере. Переключение не меняет мастер-пароль и не переводит ваши названия, логины или заметки.

Язык названия иконки PWA выбирается при установке. Если нужно изменить название уже установленного приложения, браузер может потребовать переустановку. Перед любым удалением приложения сохраните резервную копию.

4. Создание и открытие хранилища

  1. На первом экране введите мастер-пароль дважды.
  2. Используйте не менее 12 символов; лучше длинную уникальную фразу из случайных слов. Не используйте пароль от Google или другой учётной записи.
  3. Нажмите Создать хранилище. Во время вычисления ключа появится «Подождите…».
  4. Хранилище откроется. В дальнейшем вводите мастер-пароль и нажимайте Открыть хранилище.

Мастер-пароль не сохраняется и не отправляется в сеть. Храните его отдельно безопасным для вас способом. Смены мастер-пароля в этой версии нет.

Хранилище привязано к браузерному профилю и адресу приложения. localhost:4173 и 127.0.0.1:4173 — разные места хранения. Другой браузер, порт, профиль, домен или установка на телефоне могут показывать пустое хранилище. Для переноса используйте экспорт и восстановление; данные сами не синхронизируются.

5. Добавление и использование записей

  1. Нажмите Добавить запись.
  2. Заполните название и пароль либо добавьте хотя бы один API-ключ. Для записи только с ключами пароль можно оставить пустым.
  3. При необходимости добавьте логин/email, адрес сайта и заметку.
  4. Введите сайт целиком либо без https://: приложение добавит его при сохранении. Адреса приложений Android, перенесённые из Chrome, также сохраняются.
  5. Нажмите Сохранить запись. Только после сообщения об успешном сохранении запись считается сохранённой.

Поиск работает по названию, логину и адресу сайта. Пароли и заметки не участвуют в поиске. Кнопки справа позволяют скопировать логин, скопировать пароль, открыть редактор или удалить запись; наведите указатель для подсказки.

Показать в редакторе раскрывает пароль на 15 секунд. Скрыть закрывает его раньше. Для удаления нужна отдельная кнопка подтверждения. Отмена оставляет запись на месте. Удалённую запись можно вернуть из ранее созданной резервной копии.

После копирования буфер обмена автоматически не очищается. История буфера или его синхронизация в ОС могут сохранять пароли. При запрете копирования откройте запись и скопируйте значение вручную.

Несколько API-ключей в одной записи

  1. В форме записи найдите раздел API-ключи и нажмите Добавить API-ключ.
  2. Укажите название, например «Основной», «Тестовый» или «Сервер», и вставьте значение ключа.
  3. Добавляйте новые поля для остальных ключей — до 20 в одной записи. Название ограничено 100 символами, значение — 10000.
  4. Значения скрыты по умолчанию. Показать раскрывает только выбранный ключ на 15 секунд; уход в фон снова скрывает его.
  5. Значок двух наложенных листов рядом с полем копирует точное значение. Видимой надписи «Копировать» нет. Такой же значок есть у логина, пароля и результата генератора.
  6. Крестик удаляет поле из формы. Нажмите Сохранить запись, чтобы сохранить добавление, изменение или удаление ключей. Отмена оставляет сохранённую запись прежней.

Названия и значения ключей шифруются вместе с остальными полями, входят в зашифрованные копии и сохраняются при восстановлении. Можно создать запись только с API-ключами, без пароля от аккаунта. Частично заполненный ключ нужно заполнить полностью или удалить; полностью пустое дополнительное поле не сохраняется. Значения ключей не участвуют в поиске.

Копии с ключами требуют версии приложения 1.2.0 или новее. Старые копии без ключей открываются в новой версии. Не возвращайтесь к прежней версии приложения после сохранения ключей: она не умеет читать формат 2. Импорт изменённого ключа сохраняет отличающуюся запись отдельно, чтобы не потерять старое значение.

6. Генератор паролей

Откройте Генератор паролей. Выберите длину 12–64 символа и наборы символов: строчные, прописные, цифры, специальные знаки. Нужен хотя бы один набор. Ещё вариант создаёт новый пароль, Копировать помещает его в буфер.

В форме записи кнопка Сгенерировать пароль вставляет случайный пароль длиной 20 символов. Сохраните запись и установите этот пароль на нужном сайте самостоятельно. Приложение не меняет пароль аккаунта на стороннем сайте.

7. Импорт паролей из Chrome

  1. В Chrome откройте меню → Пароли и автозаполнение → Менеджер паролей Google → Настройки.
  2. В разделе Экспортировать пароли нажмите Скачать файл. Подтвердите действие паролем/PIN или средствами ОС, если потребуется.
  3. Создайте или откройте хранилище в приложении.
  4. Нажмите Импорт из Chrome, выберите полученный CSV.
  5. Проверьте числа: найденные, новые, дубликаты, пропущенные без пароля. До нажатия Импортировать записи не сохраняются.
  6. Нажмите Импортировать, проверьте несколько записей и скачайте зашифрованную резервную копию.
  7. Удалите исходный CSV безопасным для вас способом. Он содержит незашифрованные пароли; не загружайте его на GitHub и не отправляйте в чат.

Файл разбирается только локально. Обязательные колонки: url, username, password. Колонки name, note и notes необязательны. Поддерживаются UTF-8, BOM, кавычки, запятые и переносы строк. Лимит — 4 МБ и 2000 записей. Точные дубликаты пропускаются; разные версии одного аккаунта сохраняются отдельно. Пустые пароли пропускаются. Ошибка формата или слишком длинное поле отменяют весь импорт. Passkeys, карты и адреса не импортируются.

Официальная справка: экспорт паролей Chrome.

8. Резервные копии на устройстве

Откройте хранилище и нажмите Скачать резервную копию. Сохраните JSON-файл в надёжное место. Он зашифрован тем же мастер-паролем, который использовался при создании копии. Скачивайте новую копию после важных изменений и периодически проверяйте восстановление.

Старая копия не обновляется сама. Она может содержать записи, которые вы уже удалили. Сохраняйте несколько версий осознанно. Не храните мастер-пароль рядом с копией в открытом виде.

9. Восстановление и перенос

На новом устройстве или в пустом браузере: нажмите Восстановить из резервной копии на первом экране. Выберите JSON и введите мастер-пароль этой копии. Восстановленное хранилище использует пароль копии.

В существующее хранилище: сначала откройте его, затем нажмите Импортировать копию. Выберите JSON, введите пароль от копии. Записи объединятся: точные дубликаты пропустятся, изменённые версии останутся отдельными. Мастер-пароль текущего хранилища сохранится.

Неверный пароль или повреждённый файл не заменяют существующие данные. Лимит копии — 4 МБ, хранилища — 2000 записей; квота браузера может закончиться раньше. Зашифрованный JSON не открывается в Excel как список паролей — это ожидаемо.

10. Установка как PWA и работа без сети

  1. Запустите локальную версию или откройте опубликованный HTTPS-адрес.
  2. Дождитесь первой полной загрузки. Нажмите Установить, чтобы увидеть статус. Должно появиться Офлайн-режим готов.
  3. В Chrome/Edge используйте кнопку Установить в диалоге, если она доступна, либо установку приложения в меню браузера.
  4. На iPhone/iPad откройте HTTPS-версию в Safari → Поделиться → На экран Домой. Названия пунктов зависят от версии браузера.
  5. Запускайте приложение по иконке. После успешного кэширования локальная версия может работать и после остановки сервера, пока браузер сохраняет офлайн-кэш. На конкретном устройстве сначала проверьте это с тестовыми данными.

Установка зависит от поддержки браузера. Встроенные браузеры других программ могут не предлагать её. В таком случае откройте адрес в обычном Chrome/Edge/Safari. Установка PWA не публикует сайт и не синхронизирует данные с телефоном.

В кэш попадают только файлы интерфейса и руководства. Записи, пароли, мастер-ключ, CSV, Google-токены и ответы Drive в офлайн-кэш не записываются. Шифрованное хранилище остаётся в localStorage.

Без сети доступны локальные записи, поиск, генератор и файловые копии. Google Drive требует интернет. Очистка данных сайта или удаление приложения с данными может удалить и хранилище, и офлайн-кэш. PWA не заменяет резервные копии.

11. Обновление приложения

Перед обновлением скачайте копию и сохраните открытые формы. Обновите файлы локальной папки либо дождитесь обновления опубликованного сайта. Для получения новой версии локальный сервер должен быть запущен.

При обнаружении новой версии в окне Установить появится Обновить приложение. Эта кнопка блокирует хранилище и перезагружает страницу. Если кнопка не появилась, снова откройте приложение при доступном сервере/интернете; браузер проверяет обновления при загрузке. Первый переход может ещё использовать старую версию из кэша. Файлы не обновляются из GitHub автоматически.

12. Google Drive: что требуется

Наличие Google Drive не означает наличие OAuth Client ID. Client ID — публичный идентификатор программы в Google; это не пароль и не секрет.

Для опубликованного приложения владелец программы настраивает Client ID один раз для её адреса. Каждый пользователь затем нажимает Подключить Google Drive, выбирает свой аккаунт и разрешает доступ. Создавать Google Cloud-проект каждому пользователю не нужно.

Для своей локальной копии или собственного адреса может понадобиться отдельная настройка Client ID владельцем этой копии. Настройка для другого домена автоматически не подходит.

В текущем комплекте Client ID намеренно пуст: создание Google Cloud-проекта и авторизация реального аккаунта ещё не выполнены. Без них функция Drive не подключится; файловые копии работают независимо.

13. Google Drive: первичная настройка владельцем

Эти шаги выполняются один раз для приложения, а не перед каждой копией.

  1. Откройте Google Cloud Console. Выберите существующий проект или создайте отдельный проект программы. Не меняйте настройки чужого рабочего проекта без согласования.
  2. Откройте APIs & Services → Library, найдите Google Drive API и включите его.
  3. В Google Auth Platform настройте Branding, Audience и контактные данные. Для личной проверки с обычным Google-аккаунтом выберите External и добавьте свой адрес в Test users, если приложение в режиме Testing.
  4. В Data Access укажите разрешение https://www.googleapis.com/auth/drive.file. Оно относится к файлам приложения, а не ко всему диску. Для публичного распространения выполните требования Google к публикации и проверке, если консоль их запрашивает.
  5. В Clients либо APIs & Services → Credentials создайте OAuth Client ID → Web application.
  6. В Authorized JavaScript origins добавьте https://pr0tektor.github.io для опубликованной версии. Для локальной разработки добавьте http://localhost и http://localhost:4173. Origin не содержит путь, #якорь или завершающий маршрут: /Password-manager/ в этом поле не указывается. Для своей копии на другом домене используйте её точный HTTPS-origin.
  7. Для этого браузерного popup-подключения не нужен client secret или серверный redirect callback. Не помещайте client secret в код или GitHub.
  8. Скопируйте Client ID вида числа-строка.apps.googleusercontent.com.
  9. Откройте хранилище → Google Drive → Первичная настройка Google Drive, вставьте ID и нажмите Сохранить настройку. Это запомнит публичный ID в браузере.
  10. Для общей опубликованной сборки разработчик может указать этот ID в config.mjs, чтобы пользователям не приходилось вводить его вручную. Изменение config.mjs требует новой версии офлайн-кэша перед выпуском обновления.

Названия разделов Google Console могут различаться. Следуйте актуальным подсказкам Google; не обходите предупреждения о безопасности. При изменении настроек иногда нужно подождать их применения и повторно открыть приложение.

14. Сохранение и восстановление через Google Drive

  1. Откройте хранилище → Google Drive. Если Client ID настроен и есть интернет, загрузится официальный вход Google.
  2. Нажмите Подключить Google Drive, выберите аккаунт и предоставьте запрошенное разрешение. Если всплывающее окно заблокировано, разрешите его для адреса приложения.
  3. Переключение к окну Google может заблокировать хранилище — это штатная защита. Вернитесь, снова откройте хранилище и раздел Google Drive.
  4. Нажмите Сохранить копию в Drive. Приложение создаст папку Password Manager Backups, если её ещё нет, и новый зашифрованный JSON с датой. Старые файлы не перезаписываются и не удаляются.
  5. Дождитесь сообщения об успешном сохранении. Показать резервные копии покажет до 50 последних копий, созданных этим приложением и доступных текущему OAuth-клиенту.
  6. Нажмите имя копии, откройте её в Drive и скачайте файл. Для восстановления используйте раздел 9. Прямого автоматического восстановления/синхронизации из Drive в этой версии нет.

На Google передаются зашифрованный конверт, имя файла, дата и служебные метки. Мастер-пароль, открытые записи и CSV не включаются. Само подключение Google использует официальный сервис авторизации Google. Токен доступа хранится только в памяти страницы, не в localStorage, исходниках или офлайн-кэше. После закрытия страницы или истечения токена нужно подключиться снова. Подключение не даёт приложению доступ ко всем вашим старым файлам.

Кнопка Отключить Google Drive удаляет токен из памяти и пытается отозвать разрешение Google. При ошибке/отсутствии сети отзовите доступ в настройках Google-аккаунта → подключения сторонних приложений. Сохранённые копии остаются на Drive. Управлять и удалять их можно в самом Drive.

Не выполняйте сохранение несколько раз, если результат неясен: сначала проверьте список на Drive, поскольку запрос мог завершиться до потери соединения. Проверка квот, доступа или настроек может потребовать участия владельца Cloud-проекта. Тесты этой программы не заменяют реальную проверку входа и загрузки с настроенным Client ID.

15. Блокировка, удаление и сохранность

Заблокировать закрывает записи немедленно. Автоблокировка срабатывает через 5 минут бездействия, включая время в фоне или в системном окне выбора файла. Краткий переход к файлам не закрывает форму импорта: после выбора файла продолжите импорт без повторного входа. Если прошло 5 минут, хранилище блокируется до обработки файла — войдите снова. Уход в фон не продлевает срок; показанные пароли снова скрываются. При закрытии/перезагрузке страницы или переходе на другой адрес требуется новый вход. Блокировка очищает несохранённые формы; сохранённые записи остаются зашифрованными.

Сбросить локальное хранилище на экране входа полностью удаляет записи из этого браузерного origin. Для подтверждения требуется УДАЛИТЬ (DELETE в английском интерфейсе). Это действие необратимо без копии; оно не удаляет JSON на диске или в Google Drive. Восстановите копию либо создайте новое хранилище после сброса.

Данные в памяти открытого приложения не защищены от заражённой ОС, вредоносного расширения или подмены кода. JavaScript не гарантирует полное стирание строк из памяти. Надёжная мастер-фраза, обновления ОС и безопасный браузер остаются важны. Учитывайте резервное копирование профиля браузера и файлов средствами ОС.

Обновление установленной PWA: откройте приложение с интернетом → Установить → Обновить приложение, когда появится предложение. Дождитесь версии 1.2.0 внизу страницы. Не удаляйте приложение и не очищайте его данные ради обновления. Если система полностью выгрузила PWA из памяти, повторный вход необходим; мастер-пароль и ключ между запусками не сохраняются.

16. Решение проблем

  • Пустое хранилище после переустановки: проверьте браузер, профиль и точный адрес/порт. Не сбрасывайте данные наугад; восстановите копию в нужном origin.
  • Неверный мастер-пароль: проверьте язык клавиатуры, Caps Lock и пароль именно этой копии. Средств обхода или восстановления пароля нет.
  • Данные изменились в другой вкладке: снова откройте хранилище. Во избежание конфликтов используйте одну вкладку. В браузерах без Web Locks одновременная запись не имеет полной гарантии атомарности.
  • Память заполнена или сохранение запрещено: разрешите данные сайта, выйдите из приватного режима, скачайте копию. Уменьшите объём заметок или перенесите данные в браузер с доступным местом. Не очищайте хранилище до экспорта.
  • Нет кнопки установки: откройте приложение в обычном поддерживаемом браузере через localhost/HTTPS, дождитесь офлайн-готовности; проверьте, не установлено ли оно уже.
  • Не запускается без сети: офлайн-кэш мог ещё не подготовиться или был удалён. Запустите сервер/подключите интернет и откройте приложение снова.
  • Google origin_mismatch: владелец должен добавить точный origin в OAuth Client ID. Путь страницы не указывается.
  • Google access_denied: проверьте аккаунт, Test users, публикацию/политику организации и запрашиваемое разрешение.
  • Google API disabled: включите Google Drive API в проекте того Client ID, который используется приложением.
  • Google 401/подключение истекло: подключите аккаунт снова.
  • Google 403/недостаточно места: проверьте разрешения и свободное место Drive. Полная ошибка может потребовать проверки в Google Console.
  • Резервные копии не видны: проверьте Google-аккаунт и Client ID. Ручные загрузки или файлы другого приложения могут не входить в область разрешения drive.file. Их можно скачать из Drive вручную и импортировать.

17. Техническая справка

AES-256-GCM, PBKDF2-HMAC-SHA-256 с 600 000 итераций, соль 16 байт, новый случайный IV 12 байт при каждом сохранении, тег 128 бит. Формат/версия аутентифицируются через additionalData. Ключ неэкспортируемый. Старые копии формата 1 поддерживаются. При наличии API-ключей используется формат 2; версия формата аутентифицируется шифрованием, чтобы её нельзя было подменить.

В обычной работе внешние скрипты не загружаются. Для Google Drive по вашей команде загружается Google Identity Services; сеть разрешена только для собственного origin и нужных доменов Google. Отправки форм, объекты и встраивание страницы запрещены заголовками локального сервера. Для собственного HTTPS-хостинга настройте эквивалентные заголовки. Все поля записей выводятся как текст, не HTML.

Проверки для разработчика: npm run check и npm test. Это функциональные тесты, а не независимый аудит безопасности.

Справка: установка PWA, Google token model, загрузка файлов в Drive.

Password Manager — user guide

Version 1.2.0. Russian and English interfaces are included in the same app.

1. What is included

Password Manager keeps usernames, passwords, websites and notes encrypted in your browser. It includes search, a password generator, Chrome CSV import, encrypted backup files, PWA installation and optional Google Drive backups.

The package contains the source files, Russian and English guides, a printable docs/guide.html page, Windows launchers and automated tests. Click Help in the app to open the guide. No programming is required for everyday use.

This is an early release without an independent security audit. Start with test entries. A forgotten master password cannot be recovered. Signing into Google cannot decrypt a backup without its master password either.

2. First launch on a computer

Everyday use from a link

Users do not need to install Node.js or keep a server window open. The owner hosts the app once; users then open its address.

Open the app. It is hosted on GitHub Pages over HTTPS and available on computers and phones.

  1. Open the app's HTTPS address in Chrome, Edge or Safari.
  2. Choose your language and create a vault as described below.
  3. Click Install, wait for Offline mode is ready, and install from the browser menu.
  4. Launch from its icon. After successful caching, it works offline while the browser retains the app's data.
  5. Save an encrypted backup after adding important entries.

Use the same HTTPS address on a phone, then transfer the vault with an encrypted backup: data does not synchronize automatically. See section 10 for installation details.

Local development or a self-managed copy

  1. Download the GitHub repository ZIP using Code → Download ZIP, then extract it into a separate folder.
  2. You need Node.js 22 or later from the official website.
  3. On Windows, open Start.cmd / Запустить.cmd; on other systems, run npm start in the project folder.
  4. Open http://localhost:4173. Keep the server running for the first load and offline cache preparation. Press Ctrl+C to stop it.
  5. Once offline mode is ready, test reopening with the server stopped and dummy entries. Restart the server when updating your local copy.

You do not need npm install or additional package dependencies. Opening index.html by double-click is unsupported: modules, encryption and PWA features require localhost or HTTPS.

The server listens only on your computer. On a phone, localhost refers to that phone. Use the hosted HTTPS version on a phone. To move entries from localhost to the public app, save an encrypted backup first, then restore it at the new address: these are separate storage locations.

3. Choose your language

Click English in the header to switch to English. Click Русский to return to Russian. The browser remembers the selection. Changing the language does not change your master password or translate your saved entry names, usernames or notes.

The installed PWA’s icon name is chosen at installation. Changing an existing icon’s name may require reinstalling, depending on the browser. Save an encrypted backup before removing any installed app.

4. Create and unlock a vault

  1. On the first screen, enter your master password twice.
  2. Use at least 12 characters; a long, unique phrase of random words is preferable. Do not reuse your Google or another account password.
  3. Click Create vault. Key derivation may take a moment; the button shows Please wait….
  4. Your vault opens. On later visits, enter the same master password and click Unlock vault.

The master password is neither saved nor transmitted. Keep it separately in a way you consider secure. This version does not provide a master-password change feature.

Storage belongs to a browser profile and an exact origin. localhost:4173 and 127.0.0.1:4173 are different storage locations. A different browser, profile, port, domain or phone installation may start with an empty vault. Use encrypted export/import to move data. There is no automatic device synchronization.

5. Add and use entries

  1. Click Add entry.
  2. Enter a name and either a password or at least one API key. For an API-only entry, the account password can stay empty.
  3. Optionally add a username/email, website and note.
  4. Enter a full website address or omit https://; the app adds it when saving. Android app addresses imported from Chrome are also preserved.
  5. Click Save entry. Wait for the successful-save message before treating the entry as saved.

Search matches names, usernames and websites, not passwords or notes. The buttons next to an entry copy its username, copy its password, open the editor or delete it. Hover to see a label.

Click Show inside the editor to reveal the password for 15 seconds. Hide conceals it sooner. Deleting an entry requires a separate confirmation; Cancel leaves it unchanged. A deleted entry can only be recovered from an earlier backup.

The clipboard is not cleared automatically. Your operating system’s clipboard history or sync may retain copied passwords. If clipboard access is denied, open the entry and copy the value manually.

Multiple API keys in one entry

  1. Find API keys in the entry editor and click Add API key.
  2. Enter a name such as “Production”, “Test” or “Server”, then paste the key value.
  3. Add more fields for other keys, up to 20 per entry. Names support up to 100 characters and values up to 10000.
  4. Values are concealed by default. Show reveals only that key for 15 seconds; backgrounding conceals it again.
  5. The two-sheet icon beside a field copies its exact value. There is no visible “Copy” label. The same icon appears beside the username, password and generated password.
  6. The cross removes a field from the form. Click Save entry to persist additions, changes or removals. Cancel leaves the saved entry unchanged.

Key names and values are encrypted with the other fields, included in encrypted backups and preserved on restore. An entry can contain only API keys without an account password. Complete or remove partially filled key rows; completely empty extra rows are not saved. Key values are excluded from search.

Backups containing keys require app version 1.2.0 or later. Existing backups without keys still open in the new version. Do not downgrade the app after saving keys: older versions cannot read format 2. Importing a changed key preserves the differing entry separately so the previous value is not lost.

6. Generate passwords

Open Password generator. Choose a length from 12–64 characters and select lowercase letters, uppercase letters, digits and/or symbols. At least one character set is required. Generate again creates a new password; Copy copies it.

The entry editor’s Generate password button inserts a random 20-character password. Save the entry and set that password on the relevant website yourself. This app does not change third-party account passwords.

7. Import from Chrome

  1. In Chrome, open the menu → Passwords and autofill → Google Password Manager → Settings.
  2. Under Export passwords, choose Download file. Complete any operating-system password/PIN prompt yourself.
  3. Create or unlock your vault in this app.
  4. Click Import from Chrome and choose the exported CSV.
  5. Review the counts: found, new, duplicate and skipped without a password. Nothing is saved until you click Import.
  6. Click Import, check several entries, then download an encrypted backup.
  7. Remove the original CSV using a method appropriate for your device. It contains unencrypted passwords; do not upload it to GitHub or send it in a chat.

CSV processing is local. Required columns: url, username, password. Optional columns: name, note, notes. UTF-8, BOM, quoted fields, commas and embedded newlines are supported. The limit is 4 MB and 2,000 records per file. Exact duplicates are skipped; different versions of an account are preserved separately. Empty passwords are skipped. Invalid formatting or an oversized field cancels the entire import. Passkeys, payment cards and addresses are not imported.

Official help: exporting Chrome passwords.

8. Save an encrypted backup to your device

Unlock your vault and click Download encrypted backup. Keep the JSON file somewhere secure. It uses the master password in effect when the backup was created. Make a new backup after important changes and periodically test restoration.

An earlier copy does not update automatically. It may contain entries you have since deleted. Keep historical versions intentionally, and do not store a plaintext master password next to the backup.

9. Restore or move your vault

On a new device or in an empty browser: click Restore from a backup on the first screen. Choose the encrypted JSON and enter that backup’s master password. The restored vault uses the backup’s password.

Into an existing vault: unlock it first, then click Import encrypted backup. Choose the JSON and enter its password. The app merges entries, skips exact duplicates and keeps changed versions separately. The destination vault retains its existing master password.

An incorrect password or damaged file does not replace existing data. Backups are limited to 4 MB and vaults to 2,000 entries; browser storage quotas may be smaller. An encrypted JSON is not a readable spreadsheet of passwords; this is expected.

10. Install as a PWA and use offline

  1. Start your local app or open its hosted HTTPS address.
  2. Let the first load complete. Click Install to see the status. Wait for Offline mode is ready.
  3. In Chrome/Edge, use Install in the dialog if offered, or install the app from the browser menu.
  4. On iPhone/iPad, open the HTTPS app in Safari → Share → Add to Home Screen. Labels may vary by browser version.
  5. Launch it from its icon. Once cached successfully, a local installation may also reopen after the local server stops, as long as the browser keeps its offline cache. Verify this on your device with test data first.

Installation depends on browser support. Embedded browsers in other apps may not offer it; use regular Chrome, Edge or Safari instead. Installing does not publish the app or synchronize your vault with a phone.

The offline cache stores only app files and guides. Vault entries, passwords, the master key, CSV files, Google tokens and Drive responses are never written into it. The encrypted vault stays in localStorage.

Local entries, search, generation and file backups work offline. Google Drive requires an internet connection. Clearing site data or removing an installed app with its data may remove both the vault and offline cache. PWA installation is not a backup.

11. Update the app

First download an encrypted backup and save any open forms. Replace the local application files or wait for an update to the hosted site. Your local server must be running to obtain updated local files.

When a new version is detected, Update app appears in the Install dialog. It locks the vault and reloads the page. If it does not appear, reopen the app with its server/network available; the browser checks for updates on navigation. The first visit may still use the older cached version. App files are not automatically pulled from GitHub.

12. Google Drive prerequisites

Having Google Drive does not mean you already have an OAuth Client ID. A Client ID is a public identifier for an application in Google, not a password or secret.

For a hosted application, its owner configures the Client ID once for the app’s address. Each user then clicks Connect Google Drive, chooses their own account and grants permission. Every customer does not need a separate Google Cloud project.

For your own local copy or a different hosted address, that copy’s owner may need a separate configuration. A Client ID registered for another domain does not automatically work.

The supplied configuration intentionally has no Client ID. Creating a Google Cloud project and authorizing a real account have not been completed. Drive cannot connect until configured; local encrypted file backups work independently.

13. One-time Google Drive setup by the app owner

Complete these steps once for the app, not for every backup.

  1. Open Google Cloud Console. Select an existing project or create a separate project for the app. Do not modify an unrelated production project without its owner’s agreement.
  2. Under APIs & Services → Library, find and enable Google Drive API.
  3. In Google Auth Platform, complete Branding, Audience and contact details. For personal testing with a regular Google account, select External and add your account under Test users while the app is in Testing mode.
  4. Under Data Access, request https://www.googleapis.com/auth/drive.file. This covers files used by this app, rather than your entire Drive. For public distribution, complete Google’s publishing/verification requirements if requested by the console.
  5. In Clients or APIs & Services → Credentials, create OAuth Client ID → Web application.
  6. Add https://pr0tektor.github.io as an Authorized JavaScript origin for the hosted app. For local development, also add http://localhost and http://localhost:4173. Origins do not contain a path, fragment or page route: do not include /Password-manager/ in this field. For a self-hosted copy on a different domain, use its exact HTTPS origin.
  7. This browser popup flow does not need a client secret or a server redirect callback. Never put a client secret into application code or GitHub.
  8. Copy the Client ID ending in .apps.googleusercontent.com.
  9. Unlock the vault, open Google Drive → Set up Google Drive, paste the ID and choose Save configuration. This stores the public Client ID in this browser.
  10. For a shared hosted build, the developer can put that ID in config.mjs so users do not have to enter it individually. Changing config.mjs requires a new offline-cache version before releasing the update.

Console labels may change. Follow Google’s current guidance and do not bypass security warnings. Configuration changes may need time to propagate; reopen the app and try again afterward.

14. Back up and restore using Google Drive

  1. Unlock your vault and open Google Drive. With a configured Client ID and internet connection, the official Google authorization library loads.
  2. Click Connect Google Drive, choose your account and grant the requested permission. Allow the popup for this app if your browser blocks it.
  3. Moving to Google’s window may lock the vault; this is normal. Return, unlock the vault again and reopen Google Drive.
  4. Click Save backup to Drive. The app creates a Password Manager Backups folder if needed and saves a new encrypted JSON with a timestamp. Earlier backups are neither overwritten nor deleted.
  5. Wait for the success message. Show backups lists up to 50 recent backups created by this app and accessible to the current OAuth client.
  6. Click a backup’s name to open it in Drive and download it. Restore it using section 9. This release does not directly restore from Drive or synchronize automatically.

Google receives the encrypted envelope, filename, timestamp and application metadata. The master password, plaintext entries and Chrome CSV are not included. Google authorization itself uses Google’s official service. Access tokens remain only in page memory, never in localStorage, source files or the offline cache. Reconnect after the page closes or the token expires. Connecting does not grant the app access to all your older Drive files.

Disconnect Google Drive clears the in-memory token and attempts to revoke Google permission. If it fails or you are offline, revoke the permission in your Google Account’s third-party connections settings. Saved backups remain on Drive; manage or delete them in Drive itself.

If an upload result is unclear, check Drive before clicking again: it might have completed before the connection was lost. Quotas, access errors and configuration problems may require the Cloud project owner. Automated tests cannot replace a real sign-in/upload check using a configured Client ID.

15. Locking, deletion and data safety

Lock vault immediately hides entries. Automatic locking occurs after 5 minutes of inactivity, including time in the background or in the system file picker. Briefly choosing a file preserves the import form so you can continue without signing in again. After 5 minutes, the vault locks before handling the selected file; unlock it again. Backgrounding does not extend the deadline, and revealed passwords are concealed. Closing/reloading the page or navigating away requires a new sign-in. Locking clears unsaved forms; saved entries remain encrypted.

Reset local vault on the unlock screen deletes the vault for this browser origin. Type DELETE to confirm in English, or УДАЛИТЬ in Russian. Without a backup, this is irreversible. It does not delete JSON files from your disk or Google Drive. After a reset, restore a backup or create a new vault.

Data in an unlocked application’s memory is not protected against an infected operating system, malicious browser extensions or modified application code. JavaScript cannot guarantee complete erasure of strings from memory. A strong master passphrase, updated OS and trustworthy browser remain necessary. Consider how your OS backs up browser profiles and files.

Updating an installed PWA: open it online, then use Install → Update app when offered. Check for version 1.2.0 in the footer. Do not uninstall the app or clear its data to update. If the operating system completely discards the PWA process, a new sign-in is required; the master password and key are not persisted between launches.

16. Troubleshooting

  • Empty vault after reinstalling: check the exact browser, profile, address and port. Do not reset storage blindly; restore your backup at the intended origin.
  • Incorrect master password: check keyboard layout, Caps Lock and the password for this specific backup. There is no password bypass or recovery service.
  • Data changed in another tab: unlock again. Use one active tab to reduce conflicts. Browsers without Web Locks cannot fully guarantee atomic simultaneous writes.
  • Storage full or blocked: allow site storage, avoid private mode and download an encrypted backup. Reduce notes or move to a browser with available space. Do not clear data before exporting it.
  • No installation option: use a supported regular browser on localhost/HTTPS, wait for offline readiness and check whether the app is already installed.
  • App will not open offline: its cache may not be ready or may have been removed. Start the local server or reconnect to the hosted app and load it again.
  • Google origin_mismatch: the owner must add the exact app origin to its OAuth Client ID. Do not include a page path.
  • Google access_denied: check the account, Test users, publishing status, organization policy and requested scope.
  • Google API disabled: enable Drive API in the project belonging to the Client ID used by the app.
  • Google 401/session expired: connect your account again.
  • Google 403/storage full: check permissions and available Drive space. The project owner may need to inspect Google Console to resolve the exact cause.
  • Backups are missing: check the Google account and Client ID. Manually uploaded files or files owned by another app may be outside the drive.file permission; download those directly from Drive and import them locally.

17. Technical reference

AES-256-GCM, PBKDF2-HMAC-SHA-256 with 600,000 iterations, 16-byte salt, a new random 12-byte IV per save, and a 128-bit authentication tag. Format/version are authenticated through additionalData. The key is non-extractable. Legacy format 1 backups remain supported. Entries with API keys use format 2; the format version is authenticated by encryption to prevent downgrade tampering.

Normal local use loads no external scripts. Opening Google Drive on demand loads Google Identity Services. Network access is limited by policy to the app origin and required Google domains. The local server prohibits form submission, objects and framing; configure equivalent headers on your own HTTPS host. User values are rendered as text, not HTML.

Developer checks: npm run check and npm test. These are functional tests, not an independent security audit.
